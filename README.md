# 할 일 관리

하루 10~20개 정도의 할 일을 관리하는 개인용 웹 앱입니다. 서버나 설치 없이 브라우저에서 실행되고, 새로고침해도 데이터가 유지됩니다. 프레임워크와 빌드 도구 없이 순수 JavaScript로 만들었습니다.

## 주요 기능

- 할 일 추가 / 수정 / 삭제 (제목을 클릭하면 바로 수정, 삭제 후 5초간 "실행 취소")
- 완료 체크
- 카테고리 분류: 업무 / 개인 / 공부, 카테고리별 필터
- 날짜별 목록: 전날 / 오늘 / 다음날 이동, 날짜 선택
- 진행률: 선택한 날짜의 전체 진행률과 카테고리별 진행률
- 미완료 항목을 다음 날로 이월
- 브라우저 `localStorage`에 자동 저장

## 실행 방법

로컬 정적 서버로 여는 방법을 권장합니다.

```bash
python -m http.server 8000
```

실행 후 `http://localhost:8000/index.html`에 접속합니다.

`index.html`을 직접 더블클릭해서 여는 방식(`file://`)도 동작하도록 만들었습니다(ES 모듈 대신 일반 `<script>` 사용). 다만 이 방식은 아직 직접 확인하지 못했습니다.

## 사용법

| 하고 싶은 일 | 방법 |
|---|---|
| 추가 | 제목 입력 후 Enter (카테고리는 입력창 옆 드롭다운) |
| 완료 | 체크박스 |
| 수정 | 제목 클릭 (Enter 저장, Esc 취소, 빈 제목은 무시) |
| 카테고리 변경 | 항목 오른쪽 드롭다운 |
| 삭제 | 삭제 버튼, 5초 안에 "실행 취소" 가능 |
| 다른 날 보기 | ◀ ▶, 날짜 선택기, "오늘" |
| 못 끝낸 일 넘기기 | "다음 날로 이월" (선택한 날짜의 미완료 항목만 이동) |

진행률은 카테고리 필터와 관계없이 선택한 날짜의 전체 항목을 기준으로 합니다.

## 테스트

Node 없이 브라우저에서 실행합니다. 서버를 띄운 뒤 `http://localhost:8000/tests/index.html`을 열고, 탭 제목이 `PASS n/n`이면 통과입니다. 실패하면 실패한 항목이 페이지에 표시됩니다.

테스트 대상은 DOM과 무관한 순수 로직(날짜 처리, 추가·수정·삭제, 진행률, 이월)과 저장소(버전 확인, 손상 데이터 복구, 저장소 차단·저장 실패 처리)입니다. 화면 동작은 자동 테스트 없이 브라우저에서 직접 확인했습니다.

## 프로젝트 구조

```
index.html        마크업, 스타일(<style> 태그), 스크립트 로드 순서
src/
  state.js        순수 로직 (날짜, 추가·수정·삭제, 조회, 진행률, 이월)
  storage.js      localStorage 입출력, 버전·손상 처리
  view.js         DOM 렌더링과 이벤트 연결
  app.js          상태 보관, 핸들러 구현, 저장 후 재렌더링
tests/            브라우저에서 실행하는 단위 테스트
docs/
  PRD.md          제품 요구사항과 검증 결과
  superpowers/plans/   구현 계획
```

데이터 흐름은 사용자 이벤트 → 상태 변경 → 저장 → 재렌더링의 단방향입니다.

## 데이터와 저장

- 저장 위치: `localStorage`의 `todo-app:v1` 키. 형식은 `{ "version": 1, "todos": [...] }`
- 저장된 데이터가 손상되면 빈 상태로 시작하고, 원본은 `todo-app:v1:corrupt` 키에 백업한 뒤 화면에 안내합니다. 일부 항목만 손상된 경우에는 유효한 항목만 불러오고 원본을 백업합니다.
- 브라우저 저장소를 쓸 수 없거나 저장에 실패하면 화면에 안내합니다. 저장소를 쓸 수 없을 때는 탭을 닫으면 데이터가 사라집니다.
- 데이터는 브라우저와 주소(origin)마다 따로 저장됩니다. 다른 브라우저나 다른 주소에서는 보이지 않습니다.

## 검증 상태

최신 Chrome 계열(내장 브라우저)과 로컬 서버에서 확인했습니다. 자세한 결과와 미검증 항목은 [PRD](docs/PRD.md)의 "성공 기준"과 "열린 질문"에 있습니다.

- 확인함: 단위 테스트 46개, 시나리오(추가·체크·필터·이월·삭제 취소·새로고침 유지), 엣지 케이스(빈 날짜, 공백, 100자 초과, HTML 입력), 손상·차단·저장 실패, 360px 폭
- 확인하지 못함: `file://` 직접 실행, Firefox·Safari·실제 모바일 기기, 브라우저 재시작 후 유지, 스크린 리더

## 알려진 한계

- 한 항목을 편집하는 도중에 다른 항목의 제목을 바로 클릭하면, 첫 클릭은 앞선 편집을 저장하는 데만 쓰여 한 번 더 눌러야 합니다.

## 범위 밖

로그인, 서버·클라우드 동기화, 알림, 반복 일정, 우선순위, 태그, 다크모드, 내보내기/가져오기는 포함하지 않습니다.
